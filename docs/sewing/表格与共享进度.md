# 需求表与共享进度

本次仅保留两个公开入口：
- `/sewing/request`：无需登录的表格式需求单；原私密链接继续用于进度、补充说明和附件。
- `/sewing/manage`：商家待办、订单、收款。

`/sewing`跳转至需求单。独立产品、合作、故事、FAQ、微信、预览页面及旧登录／订单入口下线，使用临时重定向归并到保留入口。内容数据及旧实现保留在版本历史／后台存档，方便日后恢复。客户私密确认`/sewing/confirm`是订单操作功能，不作为公开导航。

需求单在桌面使用四列表格：联系信息、产品预算、尺码面料、设计与附件。手机逐项纵向填写，保留原幂等编号、刷新恢复、私密存储及失败重试。提交后的页面提供当前进度、下载已提交文件、补充说明和保存私密链接。

所有制作方式使用同一条八阶段流程：需求与心理预算 → 免费打样 → 样衣送校确认 → 最终报价 → 客户确认报价 → 大货与付款安排 → 生产及印花 → 交付与尾款。制作方式仅描述自行制作、采购加工或重复款，不另设简化确认流程。

时间线由同一服务端数据投影给商家和客户。客户令牌先验证当前订单授权，再读取该单并投影为阶段、状态、说明、日期；不返回work、内部客户资料、成本、供应商信息或账款明细。协助者仍受逐单授权约束。客户补充页面每30秒、返回窗口时刷新，也可手动刷新。确认页仍保留固定版本快照；当前进度与本次待确认内容分别显示。

历史在制单可以记录已知进度，但不能据此制造客户确认、报价或收付款。时间线用“历史已完成”明确区别于有系统凭证的完成状态；未知实际日期留空。历史进度不绕过数据库对新规格／报价及后续大货操作的确认门禁。补齐真实线下确认凭证即可接续业务，无需重做过去工序。未核实的金额仍不计正式统计。

项目负责人明确授权的一笔真实在制订单已经按提供资料录入数据库。客户身份、数量及实际进度只保存在受保护的订单和本地私密备份；不将真实订单数据写入Git仓库。没有创建报价、收付款或客户确认记录；尚未明确的付款方式也保持未约定。录入使用原sewing_ops_save事务，保留原SYSTEM TEST隔离证据，未创建新表或放宽权限。

验证：312项自动测试通过、1项原有可选测试跳过；新增时间线测试覆盖历史事实不伪造确认、统一制作流程及客户投影不泄漏成本；表格／时间线端到端验证包括双方逐字段一致、手机布局、旧链接归并；原提交、打样、确认、生产、收款、故障重试流程继续回归。测试示例全部使用隔离数据库和虚构名称／数量。
