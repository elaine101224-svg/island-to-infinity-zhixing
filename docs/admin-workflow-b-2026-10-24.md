# Admin workflow B · 24 October 2026

The owner selected four primary entries: Today, Semester, Members, Website. The incumbent earth/cream palette, public site content and authorization boundaries remain in place.

- Today shows upcoming semester events, overdue/blocked work, unconfirmed plans and public changes awaiting review. It uses the same semester document as the calendar/tasks, rather than the older separate schedule.
- Semester exposes Calendar, Tasks, Groups and Projects. Each item saves independently using an expected-record comparison under a database lock. Unrelated concurrent edits survive; edits to the same record return HTTP 409. The previous complete workspace, reflections, calendar and support plans remain available in low-frequency sections. Monthly review starts from existing task progress and stays a draft until explicitly saved.
- Members combines the directory, groups and login state. Directory changes synchronize planning identities and existing account names/groups in one database transaction. Creating a directory entry never creates an Auth identity or grants login. Group changes are blocked while they would invalidate existing task, responsibility or historical reflection bindings. Only the existing two designated roster editors can write; shared admin credentials alone cannot bypass that restriction.
- Website follows the public page order, starting with Our Journey. Photos and public entries expand individually. Public calendar entries can link to canonical semester events: dates, times and planning status are prefilled for review. Private locations, descriptions, notes, household data and participation evidence are never copied. Publishing refuses a linked calendar that changed since review. Public snapshots remain separate and immutable.
- Member Activity Log lives at `/members/activities`, with an authenticated workspace link. Active invited members, including unassigned members, can submit, read and edit only their own records. Direct writes, forged authors, other-account reads/writes, future dates, stale edits, paused or revoked memberships are denied. New records never enter public website content or the legacy private activity table automatically.

Data safety: a private pre-migration backup covers the workspace, directory, accounts, editorial documents and legacy tables. Existing 15 calendar rows, 9 support plans and 5 activity records are retained. All 23 approved school-email accounts keep their ordinary roles. No notification or invitation email is sent by this change. Test fixture accounts and their records are removed from the separate free test project after testing.

Verification includes real PostgreSQL tests for row ownership, atomic directory synchronization and unrelated record edits; route authentication/CSRF tests; privacy-focused publication tests; and native hosted Supabase Auth/JWT/RLS tests with two dummy accounts. Browser interaction/visual acceptance remains constrained by browser access policy; do not report it as completed.
